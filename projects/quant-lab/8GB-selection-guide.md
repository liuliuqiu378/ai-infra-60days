# 8GB 老机器模型选型建议（项目一交付件）

> **给谁看**：有一台 8GB 内存、无独显的旧机器（或任意 8–16GB 消费级电脑），
> 想本地跑一个中文大模型的人。**你不需要读完本教程**——照本文四步执行即可。
> 本文所有数字可复现，来源与检索日期逐条标注（2026-10-16）；理论背景见
> [第 10 章](../../chapters/ch10-quantization-lab.md)，体积核算脚本见
> [code/ch10/01_size_accounting.py](../../code/ch10/01_size_accounting.py)。

## 一、先算你的"真实可用预算"（Step 1）

**核心认知：8GB 是整机内存，不是模型配额。**

| 用途 | 占用 | 说明 |
|---|---:|---|
| 操作系统 + 后台 | 2.5–3.5 GB | Windows 10/11 开机实况；Linux 可低至 1GB |
| 浏览器/IDE（若同时开） | 1–3 GB | 单个现代 Chrome 标签约 150–300MB |
| llama.cpp / ollama 框架 + KV + 激活 | 1.0–1.5 GB | ctx=2048 时 7B 的 KV ≈ 0.5GB（第 4 章线性公式） |
| **留给权重** | **= 总内存 − 上面三行** | 8GB 机器通常只剩 **3–4GB**；不跑浏览器/IDE 可到 4.5–5GB |

**判定**：
- 权重预算 ≤3.5GB → 只能看 **B 档**（3B-Q4，1.93GB）
- 权重预算 3.5–5GB → **A 档**（7B-Q4，4.68GB）需腾空间，否则退回 B 档
- 权重预算 >5.5GB（16GB 机器很常见）→ 才**有资格**考虑 C 档（14B-Q2，5.77GB）

【坑】别跳过这一步直接看模型表：8GB+7BQ4(4.68GB)+3GB系统 = 7.68GB，
再开个浏览器立刻开始用交换分区——**卡顿的元凶是 swap，不是模型慢**。

## 二、三个档位（Step 2）

体积 = HuggingFace 官方文件树实测（bartowski/Qwen2.5-*，2026-10-16）；
质量锚点 = 公开评测，逐档标来源；**通用场景默认推荐 A 档**。

### A 档（主推）：Qwen2.5-7B-Instruct · Q4_K_M

- **体积**：4.68 GB（有效 bpw 4.92；16GB 内存无压力，8GB 机器需按 Step 1 腾空间）
- **质量预期**：Q4 档在 DeepSeek-V3 论文里加权平均掉幅 **0%**
  （arXiv:2505.02390，Q4_K_M 75.79 vs FP8 75.45）；Llama-3.1-8B 统一评测
  Q4_K_M 平均 69.15 vs F16 69.47（**-0.32，噪声级**，arXiv:2601.14277）。
  7B 为外推结论，但两套独立评测同指向"Q4 基本无损"。
- **速度预期**：8GB 老机器（DDR4 双通道）CPU decode 约 **8–15 tok/s**——
  可读速度；参考同级评测（Xeon 8488C 上 8B-Q4_K_M decode 5.12 tok/s，
  arXiv:2601.14277；消费级桌面 CPU 通常更快于服务器 CPU 单线程）。
- **适合**：日常对话、摘要、改写、翻译——本方案唯一"大概率满意"的档。

```bash
# 安装（一次）：ollama 或 llama.cpp 二选一
curl -fsSL https://ollama.com/install.sh | sh        # Linux/macOS
ollama run qwen2.5:7b-instruct-q4_K_M                # 自动下载 4.68GB
# 老机器务必限制上下文（防 KV 吃光内存）：
OLLAMA_CONTEXT_LENGTH=2048 ollama run qwen2.5:7b-instruct-q4_K_M
```

**验收**（3 条全过 = 成功）：
1. `ollama ps` 显示占用 ≈4.9GB（权重+KV），**系统无 swap 暴涨**（`free -h`
   的 used 中 swap 接近 0）
2. 输入 "用一句话解释光合作用"，**首字 <3s、输出连续不卡顿**
3. 连续 10 轮对话无胡言乱语、无循环复读

### B 档（轻量）：Qwen2.5-3B-Instruct · Q4_K_M

- **体积**：1.93 GB（有效 bpw 5.00）——**任何 8GB 机器零腾挪直接跑**
- **质量预期**：Q4 档质量损失同上（噪声级），但**小模型天花板本身低**：
  3B 的知识与推理上限明显低于 7B，简单任务（翻译/改写/格式化）够用。
- **速度预期**：权重仅 1.93GB，CPU decode 可到 **15–30 tok/s**（参考：
  评测中更小量化因搬运字节少而 decode 更快，Q3_K_S 9.91 tok/s vs F16
  2.83，arXiv:2601.14277）。
- **适合**：翻译、改写、离线笔记本、对质量要求不高的批量预处理。

```bash
ollama run qwen2.5:3b-instruct-q4_K_M
```

**验收**：1. 占用 <2.5GB，浏览器可同开不卡；2. decode 体感明显快于 A 档；
3. 做一个简单翻译任务结果可用。

### C 档（极限实验）：Qwen2.5-14B-Instruct · Q2_K

- **体积**：5.77 GB（有效 bpw 3.13）——**8GB 机器纸面能装，但系统+框架后
  只剩 1–2GB 给 ctx，实际很挤**；16GB 机器才谈得上舒服。
- **质量预期**：**探智边缘，任务依赖**。同为 Q2 级的 DeepSeek-V3 论文
  （arXiv:2505.02390）：加权平均掉 **8.91%**，其中 **AIME 数学从 41.66→15.41
  （-63%）**，MMLU 只 -4。闲聊尚可，**数学/代码/多步推理不可用**。
  （14B+Qwen 未直接测——本档数字是同档位外推，用前须知。）
- **速度预期**：5.77GB 权重在 8GB 机器上 decode 约 **4–8 tok/s**（可读但慢），
  且必须 `--ctx-size 2048`。
- **适合**：**仅限实验**——"就想在本机跑 14B"的验证心理；不建议作为日常
  对话模型。

```bash
ollama run qwen2.5:14b-instruct-q2_K
OLLAMA_CONTEXT_LENGTH=2048 ollama run qwen2.5:14b-instruct-q2_K
```

**验收**：1. 占用 ≤6.2GB 且 swap 不暴涨（若暴涨立即降 ctx 或换 A 档）；
2. **质量自测必须带数学题**（如"鸡兔同笼"变体）——若答错简单题即判定
"探智已触发"，按第四节回退。

## 三、速查表（Step 3 硬规则）

| 规则 | 内容 |
|---|---|
| 1 | **想正经用 14B** → 不在 8GB 本机做：上 16GB 内存机器跑 Q4_K_M（8.99GB）或用云；本机 C 档只做实验 |
| 2 | **任何档都先下 Q4_K_M**，卡了再降档（每档差 1–4GB；降档前查有效 bpw 表算清省多少） |
| 3 | **ctx 一律从 2048 起步**（KV 随上下文线性增长，第 4 章公式：7B 开 32k = KV 16GB，8GB 机器必炸） |
| 4 | **Q3 及以下必须带 imatrix**（官方数据：imatrix 让 Q4 的 KLD 降 10%，第 9 章）；ollama 现成模型已内置 |
| 5 | **验收用对基准**：聊天手感不能验 Q2；数学/代码任务才会暴露探智（AIME -63% vs MMLU -4） |

## 四、出问题怎么办（回退路径）

| 症状 | 原因 | 动作 |
|---|---|---|
| 打字半天不吐字、系统整个卡死 | swap 满了（模型+系统超预算） | 降档（A→B）或 ctx 2048→1024 |
| 输出开始复读、答错简单数学 | 低 bit 探智（Q2 特有） | C→A 档；数学/代码任务永远 Q4+ |
| 内存够但仍慢 | CPU 带宽是墙（decode 搬权重） | 接受档位速度，或升量化省字节（见图3） |
| 16GB 想跑 32B | 32B-Q4 ≈ 19GB，仍超 | 只能 Q3_K_M（≈16GB）并关一切后台，或放弃 |
